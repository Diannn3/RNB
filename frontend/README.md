# PapelLess

A cinematic introduction and a document review workspace. React, Vite, TypeScript and Tailwind; documents stay in session memory.

## Run locally

Node.js 24 or later recommended. Install the locked dependencies with `npm ci`, run `npm run build`, then `npm run preview -- --port 4173`. Open http://127.0.0.1:4173/.

Development: `npm run dev`. Verification: `npm test`; install browser binaries with `npx playwright install`, start the preview, then `npm run test:e2e`. Do not rebuild while browser tests are running.

## Working workflows

- `/`: graphite showcase with interactive evidence and separate GSAP choreography.
- `/app`: upload a digital PDF, then continue to a guided conversation. Header **New chat** starts this flow again, with confirmation before replacing existing files and answers.
- `/app/conversation`: single-composer, one-question-at-a-time interview and PDF questions; real files use manual guidance until the local agent connects.
- `/app/verification`: edit answers, inspect the working PDF preview, follow original evidence and confirm all information in a Yes/No dialog.
- `/app/export`: explicitly choose PDF or Word; preview and download confirmed information.
- `/app/sample`: explicitly fictional, cancellable deterministic sample analysis, missing answers and contextual conflicts.
- Non-fillable digital PDFs: manually add answers and export a separate answer sheet.
- Project download: available at export as **Download project file**, or in the confirmation before replacing a session. Version 3 includes revision-bound interview dispositions, conversation, current question, skipped fields, answers, review state and SHA-256 identities. Versions 1 and 2 remain supported but all historical answers must be confirmed again. Reattach original PDFs to resume. Changed documents require review again; an export stage resumes at verification.

No model is connected. The real-file workflow is manual. Signed, encrypted, XFA and image-only documents have explicit limitations. Unsupported widgets are preserved and excluded from editable/exportable entries. No documents are stored in browser databases or uploaded by this frontend. Refresh clears session state; project JSON includes answer text and should be handled as a personal document.

Original bytes are retained. Generated bytes are previewed before download. Required answers must be completed; optional blanks must be explicitly confirmed. Word exports an editable answer document, not the original PDF layout. No signatures, submission or eligibility decisions.

## Engineering notes

See [backend handoff](docs/INTEGRATION.md), [guided journey receipt](docs/GUIDED_JOURNEY_RECEIPT.md), [research decisions](docs/RESEARCH.md), [design specification](DESIGN.md), [product context](PRODUCT.md) and [dependency notices](THIRD_PARTY_NOTICES.md).

Workspace defaults to light mode. The header moon/sun button changes the workspace theme for the current session; refresh returns to light. Original PDF pages and Word previews retain paper colors.

The workspace uses one sequential flow: New chat → upload → conversation → review → export. There is no stage-navigation rail, header Save project action, sample-ready announcement, workspace eyebrow or footer strip. Fictional sample labeling stays with the conversation and document content. The supplied header wordmark remains fully visible at desktop and mobile sizes; single-line composer text is vertically centered with its send control.
